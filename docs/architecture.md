## 1. 一句话架构

**规则引擎管风险，知识库管证据，大模型只管表达。** 三者串行、职责不重叠，任何一环失效都能降级运行。

```text
用户输入
   │
   ▼
┌─────────────────┐   槽位抽取（正则，确定性）
│ app.py           │──────────────────────────────┐
│ (Streamlit UI)   │                              │
└─────────────────┘                              ▼
   │                                    ┌──────────────────┐
   │  一次输入                           │ Slots（结构化）  │
   ▼                                    └──────────────────┘
┌──────────────────────┐                          │
│ agent/controller.py  │◄─────────────────────────┘
│  状态机 + 编排        │
└──────────────────────┘
   │ ① 总是先跑            │ ② 需要时             │ ③ 最后
   ▼                       ▼                      ▼
┌────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ tools/         │   │ tools/           │   │ agent/llm.py     │
│ triage_rules   │   │ medical_search   │   │ 工具循环 + 校验   │
│ 纯函数/无网络   │   │ 纯函数/无服务     │   │ 失败→offline      │
└────────────────┘   └──────────────────┘   └──────────────────┘
   │                       │                      │
   └───────────┬───────────┴──────────────────────┘
               ▼
        ┌──────────────┐
        │ 结构化报告     │  ← 规则结果永远覆盖模型结论
        └──────────────┘
```

## 2. 模块清单

| 模块 | 职责 | 依赖 | 禁止 |
|---|---|---|---|
| `contracts.py` | 枚举、dataclass、常量、槽位判定 | 无 | 引入业务逻辑 |
| `tools/triage_rules.py` | 规则加载/校验/匹配、否定、修饰、分级 | `contracts` | 引入任何模型 SDK |
| `tools/medical_search.py` | 知识加载/校验、关键词打分、阈值过滤 | `contracts` | 访问网络 |
| `agent/controller.py` | 槽位抽取、状态机、追问决策、编排、降级 | 上面全部 | 出现 `st.*` |
| `agent/llm.py` | 配置、客户端、工具循环、JSON 校验 | `contracts`, `prompts` | 打印明文 Key |
| `agent/offline.py` | 追问模板、报告拼装、紧急卡 | `contracts` | 伪装成模型输出 |
| `agent/prompts.py` | 系统提示词、工具定义 | 无 | 散落在业务代码 |
| `app.py` | 渲染与状态 | 全部 | 在渲染路径调用模型 |

## 3. 一次输入的完整数据流

```text
1. 用户输入 "胸口压着疼，还一直出汗，大概二十分钟了"
2. controller.handle(text)
   ├─ Turn(user) 入 session.turns；累积 symptom_text
   ├─ extract_slots(text) → Slots(duration="二十分钟", severity=None, ...)
   ├─ merge_slots（只填空白，不覆盖）
   ├─ screen(symptom_text, slots) → TriageResult(level=EMERGENCY, matched=[R001])
   └─ level == EMERGENCY → 短路
        ├─ offline.build_report(...)   （不检索、不调模型）
        └─ Reply(kind="emergency", text=紧急卡, report=...)
3. app.py 渲染红色卡 + 报告，标记 session.finished=True
```

非紧急路径：

```text
screen → level ∈ {INSUFFICIENT, ROUTINE, URGENT}
  ├─ 缺槽位 且 追问次数 < 3 → 生成追问（在线模式让模型润色，失败回退模板）
  └─ 否则 → search(query=主诉+伴随) → 生成报告
                ├─ 离线：offline.build_report()
                └─ 在线：llm.run_tool_loop() → parse_json → validate_report()
                          任一异常 → offline.build_report(degraded)
```

## 4. 风险分级决策表

| 顺序 | 判断 | 结果 |
|---|---|---|
| 1 | 命中 `level=emergency` 规则且未被否定 | **EMERGENCY**（立即 120/急诊） |
| 2 | 命中 `level=urgent` 规则 | **URGENT**（24h 内就医） |
| 3 | 人群修饰生效（婴儿/老年/孕产/免疫抑制/基础病）且为 ROUTINE | 上调至 **URGENT** |
| 4 | 关键槽位缺失 | **INSUFFICIENT**（默认态，绝不当成安全） |
| 5 | 槽位齐全且无命中 | **ROUTINE** |

修饰只做"升级 + 补问"，从不做诊断。过去时表述降一级，假设/咨询句不升级。

## 5. 规则来源编号表

`knowledge/rules.json` 的 `sources` 字段引用下列编号。**规则是工程保守阈值，不是指南原文**——这一点必须在答辩时主动说明。

| 编号 | 类型 | 服务规则 | 状态 | 说明 |
|---|---|---|---|---|
| `S-ER-TRIAGE` | 急诊预检分诊类共识/规范的通用思路 | R001, R003, R004, R005, R006, R008 | **待核实具体文件与年份** | 只借用"按危险信号分级"的思路，未逐条引用条款 |
| `S-STROKE-FAST` | 公众卒中识别口诀（FAST / 中风 120） | R002 | **待核实官方科普页** | 识别要点为公开常识，不作为诊断标准 |
| `S-FEVER-ADULT` | 成人发热就医阈值的通用做法 | R009 | **待核实** | 39℃ / 3 天为工程阈值 |
| `S-FEVER-CHILD` | 儿童发热管理的公众科普（已核对 NHS 页面可访问） | R010 | 已核对链接，内容表述待医学复核 | <https://www.nhs.uk/conditions/fever-in-children/> |
| `S-PREG-ALERT` | 孕产期危险信号的公众科普 | R011 | **待核实** | 腹痛/出血/破水/胎动减少为通用警示 |
| `S-DEHYDRATION` | 腹泻脱水识别的公众科普（已核对 NHS 页面可访问） | R012 | 已核对链接，内容表述待医学复核 | <https://www.nhs.uk/conditions/diarrhoea-and-vomiting/> |
| `S-CRISIS` | 心理危机干预的通用原则 | R007 | **待核实** | 未列具体热线号码，避免号码变更导致错误信息 |

### 5.1 标注纪律

1. 拿不到确切出处就写"待核实"，**绝不**写"依据《××指南（2023）》第 4.2 条"这类精确到条款但无法核对的引用；
2. 每条规则在 `notes` 里写清适用范围与局限；
3. 提交前由知识库负责人完成一轮措辞复核（最好请医学背景的人看一眼）；
4. 复核完成后，把上表"状态"列改为"已核对 + 日期 + 链接"。

## 6. 关键设计决策（为什么这么做）

| 决策 | 原因 | 反例（原方案） |
|---|---|---|
| 追问由槽位引擎决定 | 模型输出不可复现，演示会翻车 | 让 LLM 判断"是否需要追问" |
| 四态风险 + 默认 INSUFFICIENT | 避免"未命中=安全"的隐性阴性结论 | 二态：命中/未命中 |
| 规则命中即短路 | 危险信号的处置不能被延迟 | 先检索再判断 |
| 规则结果覆盖模型结果 | 安全结论不能交给概率模型 | 让模型输出风险等级 |
| 知识条目 id/url 白名单校验 | 模型会编造来源，这是比赛硬伤 | 直接透传模型输出 |
| 否定窗口 + 假设句降权 | "我没有胸痛"误报会毁掉演示 | 纯关键词匹配 |
| pending 条目不进报告 | 未核实来源等于造假 | 有 URL 就算来源 |
| 离线模式显性横幅 | 不冒充模型能力，答辩更稳 | 静默降级 |
| 工具调用硬上限 3 轮 | 防止死循环与费用失控 | "设置合理上限"（没做） |

## 7. 数据契约（实现版）

完整定义见 `contracts.py`，此处只列关系：

```text
Session
 ├── turns: list[Turn]            # 对话历史（送模型时只取最近 6 轮）
 ├── slots: Slots                 # 结构化信息（唯一事实来源）
 ├── triage: TriageResult | None  # 规则结果（可复现）
 ├── hits: list[KnowledgeHit]     # 本次检索结果（报告只能引用这些 id）
 ├── report: dict | None          # 通过校验的报告
 ├── mode: "online" | "offline"
 └── ask_count: int               # 已追问轮次（上限 3）
```

**不可变约定**：`TriageResult` 一旦生成，模型层只能读取，不能写回。

## 8. 失败与降级矩阵

| 故障 | 检测点 | 行为 | 用户可见 |
|---|---|---|---|
| 无 API Key | `Config.mode` | 全程离线 | 橙色横幅 |
| 401/403 | `LLMError(kind="auth")` | 降级 + 提示检查 Key | 报告页顶部提示 |
| 429 / 5xx | `LLMError(kind="rate")` | 降级 | "模型服务限流" |
| 超时 | `LLMError(kind="timeout")` | 降级 | "响应超时" |
| 工具死循环 | `max_tool_rounds` | 降级 | "工具调用次数超限" |
| JSON 解析失败 | `parse_json_object` | 降级 | "输出格式异常" |
| 编造知识条目 | `validate_report` | 删除条目 + 记入 limitations | 报告里看不到假条目 |
| 规则文件损坏 | `load_rules` 抛错 | **阻断**并显示原因 | 侧边栏红字 |
| 知识库为空 | `search` 返回 `[]` | 继续，报告标注无来源 | "未检索到可靠条目" |

## 9. 安全边界（写给评审）

1. 系统输出的是**风险分层与就医建议**，不是诊断结论；
2. 所有行动建议都是"去哪一科、多久内、出现什么要转急诊"，不含药物剂量；
3. 危险信号清单限定在公开、普遍接受的紧急表现（意识改变、呼吸困难、持续胸痛、大量出血等）；
4. 未命中规则明确表述为"未发现规则覆盖的紧急信号"，而非"安全"；
5. 知识库每条都有来源，`pending` 条目不参与报告；
6. 演示数据全部合成，不采集真实患者信息；
7. 不宣称任何准确率或临床验证结果。

## 10. 后续扩展（按性价比排序）

1. **知识库扩容**（12 条 → 25 条）并补齐直达链接 —— 收益最高，无需改代码；
2. **规则来源复核** —— 把"待核实"清零，答辩时最容易被追问；
3. 槽位抽取加入少量同义词表（"拉稀"="腹泻"）；
4. 可选向量检索（`ENABLE_VECTOR=1`）—— 仅在关键词召回明显不足时再做；
5. 多轮报告增量更新（当前是重新生成）；
6. 就医科室推荐（按症状 → 科室映射表，仍是规则）。
